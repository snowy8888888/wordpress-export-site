# B2B Product Website Skill

把真实产品目录与已确认的视觉方向落地为可维护、可选型、可询价的网站。主要服务品牌商、进口商、分销商和项目采购。默认使用 WordPress、Elementor 和 WooCommerce 产品，尊重用户指定的平台与已有实现。

## 确定本次工作

- 区分整站建设、续建和局部修改。只改图片或按钮时完成相关工作与针对性回归。
- 先读会话、附件和项目进度，再核实线上现状。沿用已确认的范围、语言、设计和授权，历史记录可能被后续进度覆盖。
- 产品事实表至少包含 SKU、类别、资料页码、规格、原图、现有链接和待确认差异。双语目录冲突时标注冲突，正文先使用确定内容。
- 使用现有连接和工具能力，先读取真实 schema，再选择 API、MCP 或浏览器。可通过后台连接完成的工作不应要求用户一直保持 Chrome 前台。
- 仅询问无法从资料判断且影响实施的问题。等待某项资料或授权时继续独立工作。

## 端到端流程

1. 核实目标站点、恢复入口、当前编辑状态、插件、媒体、产品、导航、表单和商店可见性。对照真实目录与设计示意，排除未获确认的产品。
2. 以 SKU 或已有 ID 对应 WooCommerce 原生产品、分类、属性和图片。重试导入前核对已创建记录。
3. 沿用批准的视觉，先完成一个代表页面，确定产品卡片、详情、媒体、页眉页脚和表单规则，再推广到全站。
4. 完成首页、产品总览、实际分类归档、产品模板、About Us、Contact，以及范围内的 OEM & Projects、Blogs、文章与下载。合并页面时处理旧内容和链接。
5. 共享表单保存后台记录，产品页自动带入型号和来源链接。按要求配置 WhatsApp、业务通知、客户回执及邮箱连接。
6. 在授权范围内保存和发布。检查匿名访问、实际产品内容、手机布局、全部相关链接和文件。邮件分别检查记录、日志和实际收件。
7. 沿用项目状态文件记录完成证据、编辑入口、恢复点和待办。区分页面完成、询盘完成和索引状态。

## 保留关键关系

- 产品详情来自 WooCommerce，模板读取当前产品，总览和分类复用同一数据源。
- 询盘型目录通常隐藏零售价、购物车和结算入口。根据实际业务处理交易功能，不为填模板编造价格、优惠和销量。
- 产品首图、原始资料图、参数、PDF 和询价上下文按型号对应。批量换主图覆盖约定的全部产品，同时保留原图和已有相册。
- 用户要“一模一样的原图”时定位原始资产，如实说明真实像素和来源。生成、裁切或放大的图片不能标作原始高清文件。
- 场景图以真实型号为参考并逐图校对。工厂、认证、客户、出口市场、MOQ、交期和质保使用资料或用户确认。
- 原生可编辑组件和共享模板优先，局部 CSS 或集成限定作用范围并记录维护位置。
- 修改前保存受影响内容快照并检测编辑锁，修改后重新读取、刷新相关缓存并检查公开页面。工具中断后先核实现状再重试。
- “全部产品”要统计约定集合、渲染数量及唯一产品链接，不能只验首屏或将案例产品数写死在新项目中。

## 验收与回复

只报告有证据的结果，给实际页面和简短待办。视觉修改在可用浏览器中保存当前截图，无法进行视觉检查时说明缺项，不能用接口成功或旧截图替代。

凭据、令牌、授权码、私密预览链接和真实客户询盘不写入技能、项目记录或公开素材。技能提供方法，本身不扩大站点、账号、发布或邮件发送授权。
