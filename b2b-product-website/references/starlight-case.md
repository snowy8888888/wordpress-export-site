# Starlight 案例

本技能源自本次智能锁建站。下列为项目选择，其他企业按自己的产品和资料调整。记录截止 2026-11-11，实际续建需核实最新线上状态。

## 项目选择

- 英文 B2B 智能锁与门五金询盘站，域名 good.starlighthardwares.com。
- 仅目录中的 24 款产品，早期设计出现的 HLK108 和 CLK112 未进入最终范围。
- WordPress、Elementor 原生页面、Blocksy 页眉页脚、WooCommerce 产品与分类。Fluent Forms 记录询盘，FluentSMTP 对接用户确认的 Microsoft 365 邮箱。
- 暖米白、深海军蓝、少量蓝色强调、暖木门产品场景与留白。用户反复要求减少拥挤、缩小工厂媒体、改善页脚。
- 所有详情主图为对应型号安装场景，原始目录图保留在相册，网站用压缩 WebP。
- Resources 并入 About Us，旧入口永久重定向。主导航有 Products、OEM & Projects、Blogs、About Us、Contact。
- 公共 CTA 使用 Get Free Quote，OEM 使用 Sample Request 连接 WhatsApp，每个产品另有带型号和链接的 Quote on WhatsApp。
- 工厂照片来自旧站实拍，视频为核对过的官方工厂参观。美国、欧洲出口市场来自用户确认。

## 最近首页调整

工厂照片与视频改成相同尺寸的 16:9 紧凑卡片。工厂区之后直接展示 WooCommerce 全产品列表。该次工厂内容宽约 768 px，桌面产品四列、中等宽度三列、手机两列，手机工厂媒体单列。

当时核验 24 个唯一产品链接、工厂区后紧接 all-products，并在测量过的桌面和手机视口检查无横向溢出。尺寸和列数作为案例参考，不是其他项目的固定标准。

## 可复用教训

| 实际问题 | 处理 |
| --- | --- |
| 图片颜色与产品比例不一致 | 统一画幅、光线与视觉重量，逐型号核对 |
| 要原图却拿到近似生成图 | 定位原始资产，说明真实像素和生成来源 |
| 只改首页，遗漏详情主图 | 明确产品集合，逐项核对特色图和相册 |
| 工厂图片和视频太大 | 同时控制媒体与容器，统一封面和播放比例 |
| 分类链接打开 Coming soon | 检查匿名正文和 WooCommerce 可见性 |
| 菜单点击文字看不见 | 验证默认、悬停、点击、焦点和当前状态 |
| WhatsApp 藏在页脚 | 持续可见入口和当前产品预填按钮 |
| 博客像模板拼接 | 围绕选型、RFQ、样品检查写具体采购内容 |
| 有表单但邮件未验收 | 分别检查记录、两类通知、回复目标和收件 |
| 进度文件存在旧状态 | 以最新确认与实时检查继续，避免重放旧脚本 |

## 邮件边界

用户批准一次 TEST 询盘，两封都发业务邮箱，随后确认收到。它验证当时两类通知链路，未验证外部买家域名投递。技能不包含连接凭据、授权码、私密预览链接或真实询盘内容。
