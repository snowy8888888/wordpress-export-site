# WordPress 实施

## 先读真实环境

发现当前工具描述和 schema，核实站点、主题、WooCommerce 与 Elementor 的实际版本，读取受影响页面、产品、模板、菜单、CSS 和集成。避免同一按钮被主题、Elementor 和 hook 重复输出。

已有 Novamira 且支持所需能力时可通过受控 PHP 操作 WordPress。Elementor MCP 若只支持当前未启用的编辑器，则采用现有文档 API 或兼容路径，不为工具方便切换整个编辑器或主题。

配置 Automattic 远程 MCP 时核实当前官方包和客户端 schema。本项目连接使用 WP_API_URL、WP_API_USERNAME、WP_API_PASSWORD 环境变量，以及参数数组 ["-y", "@automattic/mcp-wordpress-remote@latest"]。避免使用包未支持的 URL 或密码 CLI 参数。保存配置后重载会话并列出工具，失败先看进程 stderr。技能中不保存真实连接凭据。

## 产品与共享模板

- 使用原生产品、SKU、分类、属性、特色图与相册。新建前查重，已有记录沿用 ID 和 slug。
- 规格不足时保留待确认项，目录冲突记录到事实表。
- 换主图前记录旧特色图和相册，将原始图保留为补充图，并保留已有相册、去重后核对顺序。
- 模板动态读取当前名称、SKU、图片、参数、资料和永久链接。WhatsApp 与表单上下文不能写死为示例型号。
- 目录模式同时检查详情、相关产品、归档和搜索卡片中的价格、加购与结算入口。

## 全产品集合

优先复用 WooCommerce 动态输出。小目录需要一次完整显示时，可按实际可见集合使用以下 shortcode。

```text
[products limit="-1" columns="4" orderby="title" order="ASC" visibility="visible"]
```

visible 会过滤隐藏产品，使用前核对约定集合。渲染后核对数量、唯一产品链接和图片。大目录采用分页或可访问的加载方式，使全部约定产品可达。

全产品区使用唯一锚点，例如 all-products。用户要求工厂区下方直接展示时，把真实列表作为紧接工厂区的同级区块。页内入口可指锚点，主导航 Products 有可用总览页面。

分类链接来自真实 taxonomy term。HTTP 200 可能实际是 Coming soon，必须以匿名访问核对标题和产品内容，不依赖管理员身份或私密分享参数。

## Elementor 安全保存

程序化编辑前检查编辑锁和当前基线，备份受影响文档和设置，按元素 ID 局部修改。基线有变化或其他人正在编辑时先协调。

复制区块后重新生成所有元素 ID 和 repeater _id，校验树中无重复。重复 ID 可导致子项宽度样式误命中父容器。字段和值类型以当前 schema 和已保存文档为准。

传统 Elementor 实现需注意以下问题。

- 字体与背景样式组可能需要对应启用开关。
- 深层百分比宽度可能与容器 CSS 变量冲突，优先简化嵌套或修正父布局。
- 默认 padding、子项宽度和 gap 共同参与布局计算，纯布局行应显式核对内边距。
- 手机除了子项宽度，还需调整父行方向，不假设组件 columns 自动响应。
- 免费版不一定支持组件 custom_css。必要局部样式复用 WordPress Additional CSS 或现有维护文件，并限定组件或区块范围。
- 主题设置结构随版本变化，读取实际结构后局部更新，不能覆盖整份旧主题配方。

优先使用当前文档保存 API。需要直接修改 meta 时核实兼容性、转义和缓存重建。保存后重新读取文档、核对 ID、刷新相关 CSS 和页面缓存，再检查前台。

工具中断先检查实际写入结果。大变更按可恢复批次处理，避免重复创建产品、菜单、区块或通知。

## 可见性与恢复

商店可见性、搜索引擎可见性、草稿发布和缓存分别诊断。在本次授权范围修复实际问题，修改目录可见性后验证类别与产品匿名可读。

合并页面更新导航和所有相关入口，设置无环路重定向并保留恢复记录。

局部修改保留目标文档、选项或文件快照。整站或跨模板大改保留数据库和文件恢复点，核验可读和归档完整性。私密备份放在公开网站目录之外。
