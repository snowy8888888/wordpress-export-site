# WordPress 外贸官网建站

把用户的外贸业务资料转为英文或用户指定语言、可继续用 Elementor 编辑、能展示产品并收集询盘的 WordPress 官网。用户明确指定的域名、免费版或 Pro、联系方式、素材与发布范围优先；不要重新询问已经回答过的信息。

## 按当前任务读取资料

- 新建或大改版：读 [完整建站流程](references/build-workflow.md)。先把已知需求整理成业务简报，再针对缺失且会影响实施的项目提问。
- 连接 MCP、修改 Elementor 结构或处理模板：读 [连接与可编辑结构](references/elementor-mcp.md)。
- 询盘邮箱来源、表单、投递排查或 SEO：读 [询盘与 SEO 验收](references/inquiries-seo.md)。
- 需要从零开始的提示词或先问客户的问题：读 [开场 prompt 与问题清单](references/starter-prompts.md)。用客户本次信息替换参数，不能继承其他项目的公司、邮箱或域名。

## 实施原则

1. 先查看现有站点、插件、页面、发布状态、模板及用户最近编辑。保存本次要改的页面和配置快照，避免用旧脚本覆盖用户新内容。
2. 优先用 WordPress/Elementor MCP 的对应能力；能力不足时可用已授权的 REST 接口或后台 UI。临时 PHP 仅调用明确需要的原生 API，不建立隐藏的持久代码或另一个 CMS。
3. 文字、图片、按钮、规格和页眉页脚用 Elementor 原生元素。少量 CSS/JS 用于必要的样式、筛选和交互，不把整页内容塞进一个 HTML widget。用户要求 Save as Template 时，必须提供页面内可选中的原生容器，并在编辑器验证保存入口。
4. 使用真实产品资料。不要编造工厂规模、交期、MOQ、价格、评价或认证覆盖。产品主图保留外形、比例、按钮、传感器及标识；场景图逐张与原图对比，失败就重做或使用不改变产品的合成方案。
5. 询盘邮件地址来自用户明确提供的信息或网站原有配置。区分业务收件邮箱、管理员邮箱、访客邮箱及转发目标；不能把本机用户名、用户显示名推断成邮箱。
6. 正式发布前修正预览链接、首页设置和必要的询盘路径；发布后用未登录请求验证。草稿预览、数据库字段已保存、表单返回成功都不能代替公开页面和实际收件验证。
7. 页面改动后清除相关 Elementor 渲染/CSS 缓存与站点缓存，再检查前台。每次改变性能设置后测试导航、筛选、FAQ、表单；只有出现新问题才扩大或重复检查。
8. 对不能独立完成的事项留下具体入口和原因，例如 Google 账号登录/验证、未提供的公司地址、未确认的邮箱收件。不要把这些写成已经完成。

## 建站交付

交付公开网址、可编辑页面与可复用模板入口、表单维护入口、SEO/功能核验结果、桌面和手机截图、页面配置备份，以及仍待用户补充的少数事项。说明配置备份与完整数据库/媒体/主题备份的差别。

如当前平台要求网站改动的截图证据，将截图保存为本地文件并在最终回复中直接展示。若自动审批拒绝某项改动，不绕过拒绝；完成不受影响的工作，采用能达到目标的低风险方案，并准确解释拒绝的操作及原因。
